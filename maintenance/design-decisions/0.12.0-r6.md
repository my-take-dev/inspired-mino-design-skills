# 旧0.8.0との比較に基づく判断規則の補強

## 比較範囲と指摘の判定

比較元は旧0.8.0の`180ca1f31c34dbe4c16e7246413fae0f1194d912`、作業開始headは`c4919b8`。2026-09-17確認時のPR #11 base / developは0.9.0の`9a2af5e9106d785673d00cd49ea1a546e6451372`であり、今回の試用の比較元とは異なる。0.9.0との比較試用は未実行。既存runのSHA・digestは保持する。

当初の依頼は4指摘の妥当性確認と改善。runtimeと保守領域の分離、通常回答と正式packageの分離、Windows / Linux / macOSの契約は維持する。

| 指摘 | 判定と根拠 | 変更 |
|---|---|---|
| 高impact意味照合の適用範囲 | 妥当。旧0.8.0のCore / shared-policiesは全入口でaccepted reviewを要求。開始headでは具体gateがFramingに寄り、専門入口の共通規則は未知依存の停止だけだった | 全入口が直接読むshared-policiesへ新規解釈・変更の照合を配置。自己matchedでも照合し、確認済みbaselineの再利用を明示 |
| 分類別投資の指針 | 妥当。旧0.8.0のArchitecture hard gateとreferences/workflow.mdの投資規則に比べ、分類と5要因から選択へつなぐ本文が薄い | 投資順位が対象のときだけ4分類の投資指針と非coreの価値維持を戻す |
| exact bytes回帰 | 開始headでは解消済み。8215af5のCheck.readはread_bytes→strict decodeで改行を保持し、bodyをUTF-8へ戻すためraw bodyと同じbytesになる。read_text経路ではない | 既存engineを変更せず、CRLF / CR / BOM / 不正UTF-8 / 末尾改行 / 空file / 本文だけCRLFの回帰を再実行 |
| field数・CIによる非劣化主張 | 妥当。field名の存在、platform上の構造検査、途中版を含む試用は判断品質の同等性を証明しない | README・benchmark・r5の比較説明を明確化。旧0.8.0の重要caseとの対応、共通入力とoracleによる比較をr6へ記録 |

## 規則の根拠と配置

| 分類 | 根拠 | 今回の適用 |
|---|---|---|
| source-derived principle | [文脈の言語化](../../mino-doc/16-ai-context-verbalization.md)に整理した、actor・目的・文脈によって意味を捉える原則 | AIの確信を業務意味の根拠にしない |
| source-derived principle | [事業価値とcore](../../mino-doc/03-business-value-and-core-domain.md)、[負債優先順位](../../mino-doc/04-technical-debt-goal-and-prioritization.md)、[Architecture](../../mino-doc/27-architecture-quality-strategy.md) | 差別化、変更予測、必要品質と損失へ設計投資を接続する |
| suite operationalization | statement / comparison basis / proposed status / differences、accepted review、baseline scope / revision、5要因、case / oracle | 観測可能な判定へ変換するためのsuite固有手順。公開資料の著者の定義へ帰属させない |
| repository policy | runtimeのskills境界、14,000 bytes上限、UTF-8 / LF、evaluation revision、独立比較の記録 | 共通規則の短い追加にとどめ、schemaと保守評価を通常読込へ戻さない |

意味照合の承認基準はshared-policiesに一元化し、Framingはその適用を示す。既存の確認・承認が今回の意味を覆うなら再要求しない。未照合の意味に依存しない作業、条件付き設計、reviewは完成できる。独立evaluatorの照合を人間所有の業務採用・不可逆操作の承認へ昇格させない。

suite versionは既存の維持指示に従い0.12.0のまま。r6はr5の57入力をbyte一致で保持し、5入力を追加した62ケース。C11 / C19 / C53 / C54のoracleを補強し、旧case / oracleは上書きしない。意味gateの全面的な品質保証を字句一致validatorへ追加せず、[評価記録](../evaluations/0.12.0-r6.md)で構造と試用の限界を分ける。
