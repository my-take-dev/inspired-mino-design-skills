# 実行方針と全7 Skillへの適用

初版記録: 2026-09-08。当時は既存配布物の記録を引き継ぎ、公式仕様を再取得していなかった。2026-09-10に指定された公式ガイドを再閲覧した差分は[実用性改善記録](31-practicality-refresh-20260910.md)へ記録する。

## 根拠と記述方針

前版が参照した[公式Model guidance](https://developers.openai.com/api/docs/guides/latest-model)の作業完遂、指示への追従、必要時の委譲、検証範囲の調整を、共通実行方針と各担当の手順へ反映する。出典URLは保守用の帰属Evidenceであり、Skillの実行時依存ではない。

この配布物は特定のモデル固有名詞を本文・ファイル名・表示設定へ埋め込まない。名称を削除しても、既存の判断責任、必要な深さでの検討、権限内での完遂、独立観点への委譲、意味のある検証終了条件を維持する。別モデルで同等の結果になるとの保証はしない。

low / medium / high相当の思考量配分、軽量・高速設定を使える限定taskへの委譲、親による最終照合はsuiteの運用方針である。設定が変更できない場合は現在の実行環境を維持し、Skillを読んだだけで切替済みと扱わない。

## 七つへの対応

| 担当 | 維持する実行上の改善 |
|---|---|
| Core | Evidence・権限・実効設定を分け、同じ共通規則へ集約する |
| Framing | 具体例と反例を照合し、未決事項があっても安全な条件付き成果物を返す |
| Completeness | writer / reader / 失敗経路を必要時に分担し、親が実在coverageを照合する |
| Contract | 条件別authority、操作別semantics、反証可能なoracleを維持する |
| Boundary | consumerの意味とadapterの内部実装を分け、過剰抽象化を避ける |
| Architecture | 品質・移行・復旧のtrade-offを比較し、人間所有の採用判断を残す |
| Router | 依存順・scope・revision・親の最終reviewを保持し、委譲を必須化しない |

## 固定API設定の取り扱い

前版の特定APIを前提にした識別子・parameter削除・endpoint・処理地域の固定指定は、その名前だけを消して一般規則に変換しない。専用referenceをruntime互換性の確認手順へ改めた。supported / unsupported / unknownを対象versionのEvidenceで分け、確認済みの互換性だけを設定へ反映する。

通常の設計にAPI clientやWeb閲覧は不要であり、API互換性を扱う依頼でのみこの参照を使う。実装されていないtool、非同期機能、設定切替を仮定しない。

## 評価と限界

初版の評価入力38ケースは保存する。現行の0.12.0-r2は48ケースで、判断と指示追従を別集計する。caseの形式・ハッシュ確認をモデル実行の成功と呼ばない。実run時の再現性にはmodel・実効設定をrunnerが記録する必要があるが、配布本文のモデル固定指定とは区別する。

今回は既存7 Skillを更新し、新しい独立Skillを追加していない。全OS・全モデルでの挙動を保証するものではない。
